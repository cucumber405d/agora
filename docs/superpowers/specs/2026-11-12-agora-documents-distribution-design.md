# Agora: документы и распространяемый продукт — дизайн

- Дата: 2026-11-12
- Статус: на ревью
- Основа: MVP (`2026-11-09-agora-mvp-reflection-design.md`), `main` @ `c6af144`

## 1. Цель и рамки

**Цель.** Сохранить текущую функциональность reflection-агента и:
1. научить контекст принимать документы: PDF, DOCX, PPTX, XLSX, HTML;
2. оформить Agora как законченный продукт для показа и распространения:
   - Windows-установщик;
   - мастер первого запуска с диагностикой системы и установкой Ollama;
   - скачивание моделей выбранной конфигурации;
   - релизы на GitHub;
   - README со скриншотами.

**Для кого.**
- Сам автор (портфолио, демонстрация на собеседованиях).
- Человек, получивший `Agora-Setup.exe` и не знающий ничего про Python и Ollama.

**Критерии успеха.**
- На чистой учётной записи Windows 10/11: Setup.exe → ярлык в «Пуске» → мастер → выбор конфигурации → установка Ollama → скачивание моделей → первый успешный запуск с PDF в контексте. Всё без командной строки и без прав администратора (кроме того, что требует сам установщик Ollama).
- `agora doctor` объясняет, чего не хватает.
- Релиз собирается в GitHub Actions по тегу `v*`.

**Не входит в рамки.**
- OCR сканов.
- Форматы `.doc/.xls/.ppt` — сообщаем, что формат не поддерживается.
- Подпись кода.
- macOS/Linux-установщики: на этих ОС запуск через `uv`, мастер показывает команду установки Ollama.
- Выбор отдельных моделей в мастере: пользователь выбирает конфигурацию, а не модель.
- Автообновление.

## 3. Документы в контексте

**Расширения.**
- `.pdf .docx .pptx .xlsx .html .htm` конвертируются через markitdown в Markdown.
- `.doc .xls .ppt` → пропуск с причиной `legacy_format` («сохраните как .docx/.xlsx/.pptx»).

**Новые причины пропуска** (`SkipReason`):
- `legacy_format`;
- `no_text` — конвертация прошла, но текста нет: например, скан PDF; подсказка «OCR не поддерживается»;
- `convert_failed` — исключение markitdown, детали в логе.

Существующие `too_large` и `over_budget` действуют и для документов.

**Конфиг** (`ContextConfig`):
- `max_document_mb: int = 20` — лимит размера исходного документа. Для текстовых файлов остаётся прежний лимит.
- Таймаут конвертации: 60 с на файл (`convert_timeout_s`).

**Выполнение.**
- Конвертация идёт в фоновом потоке (`asyncio.to_thread`) с таймаутом. UI не блокируется.
- В панели прогресса — этап «Context: converting N/M».
- Кеш в памяти по ключу `(path, mtime_ns, size)`: повторный запуск не конвертирует заново.

**Формат в промпте:** заголовок `### file: report.pdf (converted from PDF)`, затем Markdown. Токены оцениваются по извлечённому тексту.

**Просмотр.** Enter на документе в панели файлов открывает `ViewerScreen` с извлечённым текстом. В заголовке — оценка токенов, а если документ пропущен — причина.

## 4. Мастер первого запуска, диагностика и конфигурации

### 4.1 Когда открывается
- При старте TUI, если ни один источник конфига не найден (первый запуск).
- По F8.
- Командой `agora setup`.

`agora doctor` печатает ту же диагностику в консоль без TUI. Код возврата:
- 0 — всё в порядке;
- 1 — есть предупреждения;
- 2 — есть ошибки.

Флаг `--no-network` пропускает обращения к Ollama и интернету (используется в smoke-проверке сборки).

### 4.2 Диагностика (`SystemReport`)

Отметки: ✓ / ⚠ / ✕.

- **ОС и версия.**
- **RAM всего и свободно** (`psutil`).
- **Свободное место** на диске каталога моделей Ollama (`OLLAMA_MODELS` или `~/.ollama/models`).
- **GPU:**
  - NVIDIA: `nvidia-smi --query-gpu=name,memory.total --format=csv,noheader,nounits` → название и VRAM;
  - иначе на Windows: название через WMI/PowerShell (`Win32_VideoController.Name`), VRAM = «не определена». `AdapterRAM` ограничен 4 ГБ, ему не доверяем.
- **Ollama:**
  - установлена ли: `ollama` в PATH или `%LOCALAPPDATA%\Programs\Ollama\ollama.exe`;
  - запущена ли и какой версии: `GET /api/version`;
  - скачанные модели: `GET /api/tags`;
  - пользовательские переменные `OLLAMA_CONTEXT_LENGTH`, `OLLAMA_FLASH_ATTENTION`, `OLLAMA_KV_CACHE_TYPE`.

Каждая проверка изолирована: исключение в одной даёт ⚠ с пояснением, остальные выполняются.

### 4.3 Конфигурации (`presets.yaml`)

| Конфигурация | Требования | Генератор / критик | Скачать | Окно Ollama / `max_total_tokens` |
|---|---|---|---|---|
| Лёгкая (`light`) | RAM ≥ 8 ГБ | qwen3:4b / qwen3:4b | ~2,5 ГБ | 4096 / 2500 |
| Стандартная (`standard`) | VRAM ≥ 8 ГБ | qwen3.5:9b / qwen3:8b | ~11 ГБ | 8192 / 4500 |
| Качество (`quality`) | VRAM ≥ 12 ГБ | qwen3.5:9b / qwen3:14b | ~15 ГБ | 8192 / 4500 |

- Во всех конфигурациях: провайдер `ollama`, `think: false`, `language: auto`. Остальные параметры reflection — как в текущем конфиге по умолчанию.
- **Рекомендуемая** — самая сильная конфигурация, требования которой выполнены.
- Остальные показываются с перечнем невыполненных требований и выбираются с предупреждением.
- Если VRAM не определена — рекомендации нет, выделена «Лёгкая».
- Если места на диске меньше, чем нужно выбранной конфигурации (плюс 2 ГБ запаса), — предупреждение до скачивания.

### 4.4 Шаги мастера

1. **Диагностика** — таблица `SystemReport`, кнопка «Повторить».
2. **Конфигурация** — список трёх конфигураций с рекомендацией и предупреждениями.
3. **Ollama** — если не установлена:
   - Windows: «Скачать и запустить установщик». `OllamaSetup.exe` скачивается с `https://ollama.com/download/OllamaSetup.exe` в `~/.agora/downloads/` с прогрессом и отменой, затем запускается. Agora опрашивает `/api/version` до появления сервера. Кнопки Retry / Skip.
   - Linux/macOS: команда установки и ссылка.
   - Если Ollama установлена, но не запущена, — «Запустить Ollama».
4. **Настройки Ollama** — «Применить рекомендуемые»:
   - пишет пользовательские переменные окружения без прав администратора: `OLLAMA_CONTEXT_LENGTH` из конфигурации, `OLLAMA_FLASH_ATTENTION=1`, `OLLAMA_KV_CACHE_TYPE=q8_0`. На Windows — через `HKCU\Environment` с широковещательным `WM_SETTINGCHANGE`;
   - предлагает «Перезапустить Ollama»: завершение процессов `ollama app.exe`/`ollama.exe` текущего пользователя и повторный запуск;
   - шаг можно пропустить.
5. **Модели** — список недостающих моделей конфигурации с размерами, кнопка «Скачать»:
   - `POST /api/pull` со `stream: true`, полоса прогресса по каждой модели (`completed/total`);
   - отмена прерывает поток; повторный запуск продолжает скачивание (это делает Ollama).
6. **Готово:**
   - запись `~/.agora/config.yaml` (прежний сохраняется в `config.yaml.bak`);
   - финальная проверка: короткий запрос к генератору, затем `ollama ps` — окно контекста и `100% GPU`. Если не так, выводится ⚠ с пояснением, но мастер не блокируется;
   - переход на главный экран с новым конфигом.

После Skip на любом шаге конфиг всё равно записывается. Существующая проверка здоровья (красный бокс) покажет, чего не хватает.

## 5. Сборка, релиз и витрина

**PyInstaller (onedir, `packaging/agora.spec`).**
- Результат — `dist/Agora/agora.exe` с зависимостями.
- В сборку входят:
  - `agents/templates/*.md`;
  - `tui/agora.tcss`;
  - `setup/presets.yaml`;
  - конфиг по умолчанию;
  - данные markitdown, magika и pdfminer (через `collect_data_files`).
- Smoke-проверка после сборки: `agora.exe --version` и `agora.exe doctor --no-network` завершаются без ошибки импорта и находят ресурсы.

**Inno Setup (`packaging/agora.iss`).**
- `PrivilegesRequired=lowest`, установка в `{localappdata}\Programs\Agora`.
- Ярлык в «Пуске» и, по желанию, на рабочем столе.
- Задача «Добавить в PATH пользователя».
- Деинсталлятор удаляет только каталог программы и ярлыки. `~/.agora` и модели Ollama остаются.
- Ярлык запускает `launch.cmd`:
  - если есть `wt.exe` — `wt.exe -w new --title Agora "%~dp0agora.exe"`;
  - иначе — `chcp 65001`, `mode con cols=160 lines=45`, `agora.exe`.

**Версия и About.**
- Версия задаётся в `__version__`; первый релиз — `0.2.0`.
- `agora --version`.
- В F1 добавляется блок About: версия, GitHub, текущие модели.

**Релиз (`.github/workflows/release.yml`).** Запуск по тегу `v*` на `windows-latest`:
1. `uv sync`, ruff, mypy, pytest;
2. PyInstaller, smoke-проверка;
3. Inno Setup (`iscc`);
4. `scripts/changelog.py` — EN-части импактов после предыдущего тега → `CHANGELOG.md` и тело релиза;
5. GitHub Release с `Agora-Setup-<ver>.exe` и `Agora-<ver>-portable.zip`.

Проверяется, что тег совпадает с `__version__`.

**Витрина.**
- `README.md` (EN): назначение, скриншоты, установка в два шага, ссылки.
- `docs/user-guide.md`: файлы и документы, клавиши, конфигурации, частые проблемы.
- Скриншоты генерируются из Textual-тестов (SVG) и конвертируются в PNG скриптом.
- Раздел о SmartScreen: установщик не подписан, More info → Run anyway.
- `docs/release-checklist.md` — ручная проверка на чистой учётке.

## 6. Обработка ошибок

**Документы.** Ошибки конвертации, таймаут, пустой результат → пропуск с причиной. Запуск продолжается.

**Сеть** (скачивание установщика и моделей, Ollama API):
- ошибки и обрывы → `ErrorScreen` с Retry / Skip;
- отмена в любой момент;
- частично скачанный `OllamaSetup.exe` удаляется.

**Установщик Ollama** завершился, а сервер не появился за 120 с → «Ollama не найдена», Retry / Skip.

**Внешние команды** (`nvidia-smi`, PowerShell, `ollama ps`): таймаут 10 с; отсутствие команды → ⚠, а не ошибка.

**Конфиг.** Запись атомарная: временный файл + `os.replace`. Ошибка записи → `ErrorScreen`, прежний конфиг не тронут.

**Сборка.** Отсутствующий ресурс в exe ловится smoke-проверкой в CI до публикации релиза.

- выбор рекомендуемой конфигурации — таблица сценариев «железа» (нет GPU, 8 ГБ, 12 ГБ, VRAM неизвестна, мало диска);

**Документы:**
- маленькие фикстуры PDF/DOCX/PPTX/XLSX/HTML в `tests/fixtures/docs/` (генерируются скриптом один раз и коммитятся);

- `httpx.MockTransport`, включая обрыв посреди потока;

**TUI:**
- Pilot-тесты мастера: полный проход, Skip, отмена скачивания, ошибка сети, автозапуск при отсутствии конфига, F8;

**CLI:** `doctor` (вывод и коды возврата), `setup`, `--version`.

**Интеграционные** (`-m integration`, вне CI): реальная Ollama (pull маленькой модели) и реальный PDF.

**Сборка:** smoke-проверка exe в `release.yml`, ручной `release-checklist.md`.
